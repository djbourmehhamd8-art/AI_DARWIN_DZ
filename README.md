# 🛡 DARWIN DZ — بوت تلغرام للأمن السيبراني (v4.3.0)

> **جديد في 4.3:** **العالم المباشر** — رادار طائرات حي (`/radar /flight /plane /squawk`)، METAR والطقس والـISS والطقس الفضائي والزلازل، راديو الإنترنت وحاسبات اللاسلكي (`/freq /wave /morse /qcode /grid /fspl`…)، أدوات استخبارات سلبية جديدة (`/subdomains /asn /exposure`…)، و**39 بوابة ويب** تُفتح داخل تيليجرام (`/portals`).
>
> **سابقاً في 4.2:** محادثة طبيعية (تحيات وآداب، وتحليل فوري لأي رابط/هاش/CVE/IP/نطاق ترسله وحده)، **تأريض CVE** ببيانات NVD وCISA KEV وEPSS الحقيقية، زر **✅ دقّق** لمراجعة الإجابة، أدوات النطاقات (`/domain /dns /whois /cert /webhead`)، `/footprint` لفحص المعرّفات العامة بضوابط خصوصية، ودليل 97 أداة وتوزيعة أمنية (`/toolkit`).
>
> **سابقاً في 4.1:** تفعيل صارم للمجموعات (لا يجيب أحداً في مجموعة غير مفعّلة)، حدود رسائل يومية لكل مستخدم ولكل مجموعة ولكل البوت من لوحة المدير، بحث ويب متين بعدة مزوّدين (Brave / SearXNG / DuckDuckGo / Wikipedia) مع كشف الحظر، تقرير يومي للمدير، وضع صيانة محفوظ، وإعداد المستودع لـ GitHub (CI + SECURITY). التفاصيل في [`CHANGELOG.md`](CHANGELOG.md).

نموذج ذكاء اصطناعي متخصص في الأمن السيبراني، يعرّف نفسه باسم **DARWIN DZ**. يعمل على **Termux أو أي VPS (مثل FadeHost)** بمتطلب واحد: `requests`، مع واجهة متوافقة مع OpenAI.

## 🚀 النشر على VPS (FadeHost أو غيره)
```bash
unzip darwin_dz.zip && cd darwin_dz
sudo bash deploy/install_vps.sh           # مستخدم محدود + venv + خدمة systemd + نسخ احتياطي يومي
sudo nano /opt/darwin_dz/.env             # TELEGRAM_TOKEN و API_KEY و ADMIN_IDS
sudo -u darwin bash -c 'cd /opt/darwin_dz && venv/bin/python main.py --check'   # فحص الجاهزية
sudo systemctl start darwin && journalctl -u darwin -f
```
الدليل الكامل: [`deploy/FADEHOST.md`](deploy/FADEHOST.md). للتحديث من GitHub: `bash deploy/update.sh`.

## 🔒 الوصول والمجموعات
- **بوت خاص:** من ليس لديه صلاحية يرى شاشة توضح ذلك وزر **طلب صلاحية** يصل للمدراء مع أزرار موافقة/7 أيام/رفض/حظر. صلاحية مؤقتة (1/7/30 يوماً)، ودور **مشرف** بصلاحيات أقل.
- **المجموعات:** اكتب `DZ سؤالك` فيردّ البوت في خيط. **كل مجموعة يجب أن يفعّلها مدير** (زر عند إضافة البوت، أو `/allowgroup`)؛ لا الأعضاء المعتمدون ولا المدراء يفتحون مجموعة غير مفعّلة. ملاحظة تيليجرام: اجعل البوت **مشرفاً** أو عطّل Privacy Mode من @BotFather ليقرأ رسائل «DZ …».
- **الحدود اليومية** (لوحة المدير ← 📊): افتراضي لكل مستخدم، افتراضي لكل مجموعة، وتخصيص لأي مستخدم أو مجموعة من بطاقته (`0` = بلا حد).

## 🔎 البحث في الويب
يبحث تلقائياً عندما يحتاج السؤال معلومات حديثة (`/web` للتحكم، `/search سؤال` للإجبار) ويرفق المصادر. المزوّدات بالترتيب: **Brave API** (إن وُضع `BRAVE_API_KEY`) ← **SearXNG** (إن وُضع `SEARXNG_URL`) ← **DuckDuckGo** ← **DuckDuckGo Lite** ← **Wikipedia** (احتياطي مضمون للأسئلة المعلوماتية). المزوّد المحجوب يُتخطى 5 دقائق. للمدير: `/websearch` أو زر «🔎 اختبار البحث» يعرض حالة كل مزوّد. **على سيرفرات VPS كثيراً ما يحظر DuckDuckGo عناوين مراكز البيانات؛ مفتاح Brave المجاني هو الحل الأوثق.**

## 🔑 مفاتيح API متعددة مع تحويل تلقائي (جديد)
ضع مفاتيح كثيرة **من نفس المزوّد** وإذا تعطّل أحدها ينتقل البوت للتالي فوراً دون أن يلاحظ المستخدم:
```
API_KEY=key1
API_KEYS=key2,key3,key4      # أو API_KEY_2=... API_KEY_3=...
KEY_STRATEGY=failover        # failover (افتراضي) | roundrobin لتوزيع الحمل
```
- **متى يُعتبر المفتاح معطلاً؟** 401/403 (ملغى) و402 (انتهى الرصيد) يستريح ساعة · 429 دقيقة · أخطاء الشبكة/5xx نصف دقيقة. ثم يعود تلقائياً للمحاولة.
- أخطاء الطلب نفسه (400…) لا تحرق بقية المفاتيح.
- المدير يتلقى تنبيهاً عند تعطل مفتاح وعند عودته، وأمر/زر `/keys` يعرض الحالة (المفاتيح مقنّعة) و`/status` يعرض عدد المتاح.
- كل المفاتيح تُحجب من السجلات.

- إضافة إغلاق صريح لجلسات HTTP الخاصة بتيليجرام وAI عند الإيقاف، وفحص سلامة SQLite قابل لإعادة الاستخدام.

## 🆕 ما تغيّر في 3.2 (تنظيم المحادثة والاحترافية)
**ردود أكثر تنظيماً**
- محوّل Markdown → HTML جديد لتلغرام: عناوين، قوائم متداخلة، اقتباس، روابط، مائل/عريض/مشطوب، **جداول تتحول إلى قوائم مناسبة للجوال**، وإغلاق تلقائي لكتل الكود غير المغلقة. يضمن وسوماً متوازنة فلا يُرفض الرد أبداً (وإن رُفض يُعاد إرساله نصاً عادياً).
- الرد المتدفق صار **منسّقاً أثناء الكتابة** (لا تظهر نجوم `**` خام)، والردود الطويلة تُقسَّم على عدة رسائل **دون كسر كتل الكود** (تُغلق وتُعاد فتحها).
- تعليمات الأسلوب للنموذج: خلاصة في سطر، ثم أقسام بعناوين عريضة وأيقونة، نقاط قصيرة، بلا جداول، وخطوة تالية واحدة.
- مخرجات الأدوات قابلة للنسخ بلمسة: الهاشات، المؤشرات IOC، كلمة المرور المولّدة، نتائج فك الترميز وDefang داخل `code/pre`.

**واجهة المحادثة**
- أزرار تحت كل إجابة: 🔁 إعادة · ➕ أكمل · ✂️ اختصر · 🌐 ترجم · 🆕 جديدة · 🏠 القائمة.
- زر ⏹ إيقاف يظهر أسفل الرد أثناء كتابته (يعمل أيضاً مع أدوات الذكاء الاصطناعي، وكان `/stop` سابقاً لا يوقفها).
- مؤشر «يكتب…» يبقى ظاهراً طوال التوليد.
- رسالة طلب المدخل **تُحرَّر مكان القائمة** وتُحذف بعد الإجابة، فيبقى الشات نظيفاً.
- **أسلوب الرد** من الإعدادات: ⚡ مختصر · ⚖️ متوازن · 📚 مفصّل.
- عند الفشل زر «🔁 إعادة المحاولة» بدل رسالة خطأ صامتة.
- مدير: زر/أمر 🩺 `/status` (مدة التشغيل، ردود قيد التوليد، حجم القاعدة).

**أخطاء أُصلحت**
1. **مفتاح API حقيقي كان داخل `.env.example`** (والسجل يقول إنه أُلغي). حُذف؛ لا تضع مفاتيح في ملفات المثال أبداً، وأي مفتاح شاركته سابقاً اعتبره مكشوفاً.
2. رد غير متوقع من مزوّد الـAPI (JSON ناقص) كان يرمي استثناء ويترك المستخدم أمام «…» للأبد؛ صار رسالة خطأ مع زر إعادة.
3. أي استثناء داخل توليد الرد يُلتقط ويُبلَّغ للمستخدم بدل الصمت.
4. أدوات الذكاء الاصطناعي (`/cve /ir /sigma ...`) لم تكن تأخذ قفل المحادثة فقد تتداخل مع رد آخر في السجل؛ صارت تأخذه.
5. حارس الأسرار كان يحذف رسالة المستخدم ويُنبّهه حتى لو رُفض طلبه بسبب حد المعدّل؛ صار فحص الحد أولاً.
6. رد تلغرام «message is not modified» لم يعد يُعامل كخطأ، فلا تُرسل رسائل مكررة.
7. ترحيل تلقائي لقواعد البيانات القديمة (عمود `detail`) دون فقدان بيانات.

## 🆕 ما تغيّر في 3.1
**ميزات**: واجهة أزرار كاملة مع حالة انتظار المدخل (تنتهي بعد 5 دقائق ويلغيها أي أمر) · أدوات `decode` `cvss` `ip` `defang` `sigma` ·
حذف كلمة المرور المولَّدة تلقائياً بعد دقيقة · «احذف بياناتي» بتأكيد · احتفاظ محدود بالسجل `RETENTION_DAYS` (افتراضي 30 يوماً).

**ثغرات أُصلحت**:
1. **تسرّب التوكن إلى السجل**: أخطاء `requests` تحمل الرابط كاملاً (`/bot<TOKEN>/...`) فكانت تُكتب في `data/bot.log`. أُضيف مرشّح يحجب التوكن ومفتاح API وأي Bearer/توكن بوت من كل السجلات والاستثناءات.
2. **ReDoS في `/ioc` و`/url`**: نص من 30 ألف حرف على شكل `a.a.a.` كان يعطّل المعالجة 43 ثانية (تعبيرا النطاق والبريد). استُبدلا بتجزئة خطية وسقف للمدخل، والآن 0.01 ثانية.
3. **حقن التعليمات عبر `/system` والذكريات**: النص الذي يكتبه المستخدم كان يأتي بعد تعليمات الأخلاقيات. أُضيفت قواعد نهائية `SAFETY_TAIL` تُلحق آخراً بكل prompt وتعامل الملفات والسجلات كبيانات لا كأوامر.
4. **أسرار تُحفظ وتُرسل للنموذج** عبر الذكريات والتعليمات الخاصة والتذكيرات: صارت تمرّ على حارس الأسرار قبل الحفظ. وأُضيفت صيغ: JWT, SendGrid, GitLab, npm, Discord, Azure, Basic auth.
5. **تنزيل ملفات بلا سقف فعلي**: كان يعتمد على الحجم المُعلن فقط؛ صار التنزيل متدفقاً ويتوقف عند الحد.
6. **نمو الذاكرة**: أقفال المحادثات ومحدّد المعدل كانت تكبر بلا حد؛ صارت تُنظَّف.
7. **أمر المدير بلا تأكيد**: البث كان يُرسل فوراً؛ صار بمعاينة وتأكيد، وكل إجراء مدير يُفحص على الخادم (لا يكفي إخفاء الزر).
8. `.env` يُضبط على `chmod 600` عند التثبيت، ويحذّر البوت عند التشغيل إن كان مقروءاً لغيرك.

⚠️ **تنبيه مهم**: النموذج الافتراضي `notrack-uncensored` غير مقيَّد من جهة المزوّد، فالأخلاقيات الدفاعية تعتمد على الـprompt وحده، ولا يمكن لأي prompt ضمان الالتزام 100%. للنشر لجمهور واسع غيّر `MODEL` و`API_BASE_URL` إلى نموذج بضوابط أمان، وأبقِ `PUBLIC=false`.

## أمان التشغيل
- افتراضياً `PUBLIC=false`: لا يستخدم البوت إلا المدراء والمسموح لهم.
- لا ترفع ملف `.env` لأي مكان، وإن تسرّب مفتاح فأنشئ غيره فوراً.
- الفحص المحلي للروابط والترويسات **إرشادي**: غياب المؤشرات لا يعني الأمان.
- يُنصح بسقف صرف يومي للمفتاح من لوحة المنصة.
